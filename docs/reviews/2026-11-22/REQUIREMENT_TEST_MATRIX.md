## Evidence levels

- **Local unit/property:** Go logic, temporary bbolt files, transactions, reopen/corruption fixtures and bounded fuzz/property checks. Reopen is not an abrupt process or machine failure.
- **Fake Kubernetes/controller:** client-go fake objects/reactors or an in-memory execution fixture. No real scheduler, kubelet, CNI, runtime, container or physical signal is exercised.
- **HTTP:** `httptest` handlers or real loopback HTTP/TLS/SSE transport. HTTP does not imply workload execution.
- **Subprocess interoperability:** `TestPythonClientAgainstRealAPIAndController` launches the Python client against the real Go API/store/controller and a fake execution backend. Its submitted command intentionally must never execute.
- **Manual native/container packaging:** only the compiled CLI and restricted Linux image exercises recorded in the historical report. These are not automated fresh-cluster restore tests or sandbox canaries.

## Store and phase decisions

The actual store is **bbolt**, with synchronous transactions and one exclusive API owner per private database. A second replica opening the same file is refused. Leader election alone would not turn this into shared durable storage or fence a stale physical workload. History/events live in this application database, not Kubernetes etcd.

**Architecture proposal before Phase 2:** choose a shared PostgreSQL-backed authority for future admissions, task-bound identity, gateway reservation/settlement and side-effect journal before implementing those features. Keep transactionally related admission/quota/event records together and define durable outbox, operation IDs, compare-and-swap ownership/fencing and restore semantics. Require failure tests for ambiguous commits, lease loss, gateway accounting and publication before replicas become supported. This is a proposed production direction, not an implemented adapter, accepted schema or HA claim. The current embedded alpha remains supported as a single owner; there is no dual-write migration or gateway implementation in this review.

The supplied suggestion to narrow Phase 0 to C1–C10/C12 on kind, and defer C11/C13/C14/C15, is a **local work track**, not completion of the original whole requirements. [Decision 0006](../../decisions/0006-restore-epochs-and-cause-evidence.md) records the narrower local qualification target explicitly. Local kind fault tests could add useful control-plane evidence but cannot waive the EKS/node/runtime/CNI qualification required for Phase 1. A missing required sandbox runtime must block execution; ordinary-container fallback is not an acceptable shortcut. No automatic replay or policy/gateway selection follows from this review.
